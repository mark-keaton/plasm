# The one way to build an application with Plasm

Store the domain's own records, and write each fact about the data once, in
the type if F# can say it there. There is no second style.

The template is this way as a project that builds and passes its tests:
`dotnet new install Plasm.Templates`, then `dotnet new plasm-api -n MyApp`.

## Types

A single-case wrapper (`OrderId of int64`) is stored as its value. A type
with a `create` function is read back through it, so a stored value the
domain refuses is an error, never a value.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
/// Only valid quantities exist; the database cannot smuggle in a zero.
type Quantity =
    private
    | Quantity of int
// ...
    static member create(v: int) : Result<Quantity, string> =
        if v > 0 then Ok(Quantity v) else Error $"quantity must be positive, got {v}"
```

A fieldless union is stored as its case name. A union with fields is spread
over columns: a cancelled order's reason is stored in `status_reason`.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
type OrderStatus =
    | Draft
    | Published
    | Cancelled of reason: string
```

A typed id is a reference to the record whose key it is. Registered
`Scalar.*` mappings override these conventions.

## The record

The record says how it is stored. It names its table with `[<Table>]`; its
key is its field named `Id`, generated by the database when it is an integer;
a column is named after its field, in snake_case.

A list, record or option of a stored record that holds the owner's key is
owned: its own rows, read with the owner in one batched command per list, in
the order of their key, and written with it by difference. A list of stored
records that do not hold it is linked through the join table its field names.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
[<Table "articles">]
type Article =
    { Id: ArticleId
      Title: string
      [<JoinTable "article_tags"; OrderedBy(nameof the<Tag>.Name)>]
      Tags: Tag list }
```

What no type can say is an attribute on the field: `[<Unique>]`,
`[<Version>]`, `[<OrderedBy>]`, `[<Generated>]`, `[<NotReference>]`. The
attributes live in `Plasm.Annotations`, which has no dependencies, so a domain
shared with a Fable client can carry them. Anything the types leave ambiguous
is an error when the model is built.

The model is the list of records that are not owned:

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
module Db =
    let all = [ typeof<Customer>; typeof<Product>; typeof<Order>; typeof<Payment>; typeof<Article>; typeof<Tag> ]

    /// Checked once at start-up; every problem is reported with model and field.
    let model = Model.buildOrFail [] all
```

## Other aggregates

Another aggregate is referred to by id and reached by a query: a join,
`exists (plasm { ... })`, or a second query bound with `let!`.

<!-- from: examples/Plasm.Examples/Queries.fs -->
```fsharp
let unpaid (q: Query<Order>) =
    plasm {
        for o in q do
            where (not (exists (plasm { for p in referring<Payment> o do where (p.Status = Succeeded) })))
    }
```

## Writes

Writes are steps of a typed transaction, `Tx<'T, 'E>`, with your own error
type, run by `repo.Transact`. Plasm validates no input: the domain's
constructors do. A constraint with PostgreSQL's default name comes back as the
field's error.

<!-- from: examples/Plasm.Examples/Writes.fs -->
```fsharp
let checkout (customer: Customer) (lines: OrderLine list) (now: DateTime) : Tx<Customer * Order, Refusal> =
    transaction {
        let! stored = Tx.insert customer
        let! order = Order.create stored.Id lines now |> Tx.ofResult Domain
        let! placed = Tx.insert order
        return stored, placed
    }
```

## A repository is started, and checked as it starts

`Repo.Start` translates every query value an assembly defines and compares the
model with the database; by default either problem fails start-up, naming
every one. `RepoOptions.Queries` and `RepoOptions.Schema` turn each down to
`Warn` or `Ignore`. `repo.Ddl()` prints the tables the model expects.
[Starting a repository](../guide/starting-a-repository.md) has the detail.
