# Types and records

Plasm stores the domain's own types. Most of how a value is stored follows
from its type, so there is no mapping to write. The examples are the shop of
[`examples/Plasm.Examples/Model.fs`](../../examples/Plasm.Examples/Model.fs).

## Ids

A single-case wrapper is stored as its value. Each record gets its own id
type, so mixing a `CustomerId` with an `OrderId` does not compile.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
type CustomerId = CustomerId of int64
type OrderId = OrderId of int64
type ProductId = ProductId of int64
```

A field of another record's id type is a reference to that record:
`OrderLine.ProductId` references `products`. `[<NotReference>]` says a field
is only a value.

## Validated values

A type with a `create` function is read back through it. A stored value the
domain refuses is an error when it is read, never a value in your program.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
type Quantity =
    private
    | Quantity of int

    member q.Value =
        let (Quantity v) = q
        v

    static member create(v: int) : Result<Quantity, string> =
        if v > 0 then Ok(Quantity v) else Error $"quantity must be positive, got {v}"
```

## Unions

A fieldless union is stored as its case name:

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
type PaymentStatus =
    | Pending
    | Succeeded
    | Failed
```

A union with fields is spread over columns. `OrderStatus` is stored in
`status` and `status_reason`, so an order cannot be cancelled without a
reason, in F# or in the database:

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
type OrderStatus =
    | Draft
    | Published
    | Cancelled of reason: string
```

## Stored records

A record names its table. Its key is its field named `Id`, generated by the
database when it is an integer. A column is named after its field, in
snake_case. What the types cannot say is an attribute on the field.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
[<Table "customers">]
type Customer =
    { Id: CustomerId
      Name: string
      [<Unique>]
      Email: string }
```

| Attribute | What it says |
|---|---|
| `[<Table "name">]` | the record's table |
| `[<Unique>]` | the field is unique; a violation is that field's error |
| `[<Version>]` | the field counts the record's writes, for optimistic concurrency |
| `[<OrderedBy>]` | the order an owned or linked list is read in |
| `[<JoinTable "name">]` | the join table a linked list goes through |
| `[<Generated>]`, `[<Assigned>]` | whether the database or the application gives the value |
| `[<NotReference>]` | an id-typed field that refers to nothing |

The attributes live in `Plasm.Annotations`, which has no dependencies.

## What a record owns

A list, record or option of a stored record that holds the owner's key is
owned. An order owns its lines: they are read with it, in the order of their
key, and written with it by difference.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
[<Table "orders">]
type Order =
    { Id: OrderId
      CustomerId: CustomerId option
      Status: OrderStatus
      Total: decimal
      PlacedAt: DateTime
      [<Version>]
      Version: int
      Lines: OrderLine list }
```

Nothing is loaded lazily and nothing is left unloaded: an empty list always
means the order has no lines.

## What a record links to

A list of stored records that do not hold the owner's key is linked through a
join table. Writing the article writes only the links; a tag is a shared row.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
[<Table "articles">]
type Article =
    { Id: ArticleId
      Title: string
      [<JoinTable "article_tags"; OrderedBy(nameof the<Tag>.Name)>]
      Tags: Tag list }
```

## A list of plain values

A list of scalars is one array column in its owner's row, from the type alone.
A scalar here is a built-in type, a single-case wrapper, a type read through
its `create`, or a fieldless union, so `string list` is `text[]` and a
`CustomerId list` over `int64` is `bigint[]`. What the list holds decides: a
list of stored records is owned or linked; a list of scalars is an array; a
list of anything else is refused, and `[<Json>]` stores it as one document
instead. The array is read and written whole and is never NULL, since an empty
list is an empty array. Each element is read as its own column would be. A
query tests an array with `List.contains` (`= ANY`) and `List.isEmpty`
(`cardinality`), and refuses anything else over it by name.

## The model

The model is built from the records that are not owned. Anything the types
leave ambiguous is an error here, reported with the record and the field.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
    let all = [ typeof<Customer>; typeof<Product>; typeof<Order>; typeof<Payment>; typeof<Article>; typeof<Tag> ]

    /// Checked once at start-up; every problem is reported with model and field.
    let model = Model.buildOrFail [] all
```

## The rules stay in the domain

The rules are plain functions over the records, with no persistence in them.
Plasm stores the record they return and validates nothing itself.

<!-- from: examples/Plasm.Examples/Model.fs -->
```fsharp
    let cancel (reason: string) (order: Order) : Result<Order, OrderError> =
        match order.Status with
        | Cancelled _ -> Error AlreadyCancelled
        | _ when String.IsNullOrWhiteSpace reason -> Error ReasonRequired
        | Draft
        | Published -> Ok { order with Status = Cancelled(reason.Trim()) }
```
