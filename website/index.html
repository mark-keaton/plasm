Queries.fs
/// A page of orders, each with its lines: two commands however long the page.
let orderPage page size (q: Query<Order>) =
    plasm {
        for o in q do
            orderByDescending o.PlacedAt // the key is appended as a tiebreaker
            skip (page * size)
            take size
    }
2 commands at 20, 100 or 1,000 orders lines read for the selected page only no cartesian product

C# outside, F# inside

Modern C# reads F# unions as unions. So the boundary is one F# type: your C# passes plain arguments and a cancellation token, and gets back a union the compiler makes it handle case by case.

/// `assignee` starts work on the card, if the board's limit allows it.
member _.StartAsync(card: Guid, version: int, assignee: string, cancellationToken: CancellationToken) : Task<ChangeOutcome> =
    match field "assignee" Person.create assignee with
    | Error problems -> Task.FromResult(ChangeOutcome(View.invalid problems))
    | Ok who -> change card version (Card.start who (clock ())) cancellationToken

C# writes no query

Queries and transactions stay in F#. Each endpoint is one call.

A new outcome breaks the build

The switch has no default arm. Add a case in F#, and every C# switch that misses it stops compiling.

Nothing null crosses

A missing or null argument is refused while the request is read, before F# is called.

AOT first, always

Every commit is compiled natively and must print what the runtime prints, with no trim warning naming Plasm.

Six things it won't do behind your back

Each one is an executable Gherkin scenario, run against a real PostgreSQL database.

No hidden database access

What a record owns or links is read with it, as a plain field. Nothing is loaded lazily, and nothing is left unloaded.

Nothing runs client-side by accident

A predicate that cannot be translated fails with the expression named.

No N+1, no cartesian products

Each owned or linked list is one command per batch of owner keys, however many owners are read.

Partial data cannot destroy data

An update writes only the columns that differ. A projection is not a record and cannot be written back.

Concurrency is checked

By a version field, or by every column of the record the change was made from, in the same command.

Problems surface at start-up

Starting a repository translates every query value and compares the model with the database, naming each problem.

Writes are transactions
transaction {
    let! order = Tx.oneAsSeen (orderById id, seen) |> Tx.orReject (Missing "order")
    let! changed = decide order |> Tx.ofResult Domain
    return! Tx.update (order, changed)
}
