# Where PostgreSQL and SQLite differ, for the docs page on differences.
# Each line: what differs<TAB>on PostgreSQL<TAB>on SQLite<TAB>where it is stated, and
# `tests` after a difference of the tests' own, which docs/sqlite.md leaves out.
# Scenarios that run on one database only are in postgres-only.txt and
# sqlite-only.txt; this list is the rest.
A key of decimals	keyed by value: numeric keys compare by value	refused when the repository is made (2.0 and 2.00 would be two keys)	providers.feature: A model keyed by a decimal is refused when the repository is made, by a dialect with exact hooks
A decimal's scale	a numeric(p,s) column fixes it (2.0 stored as 2.00)	TEXT keeps the scale written (2.0 stays 2.0); compared, ordered and added by value	tests/Plasm.TestDomain/Database.fs: schemaSql, schemaSqlite
A CHECK on a decimal (the test schema's)	compares numerics exactly	CAST(x AS REAL) >= 0: a sign test only, not an exact comparison (text compared with 0 is always greater)	tests/Plasm.TestDomain/Database.fs: schemaSqlite	tests
A transaction's identity (test steps)	txid_current()	none: the transaction object stands for it	tests/Plasm.Specs.Steps/TransactionSteps.fs: TxSteps.txid	tests
A writer waiting for another	waits on the row it locks	waits at BEGIN IMMEDIATE for the database, in tries of a second that hear cancellation, up to SqliteOptions.BusyTimeout	src/Plasm.Sqlite/Sqlite.fs: BeginTransaction; core.feature: Cancellation reaches database execution
A window SUM or AVG of decimals	SUM/AVG over numeric	plasm_decimal_sum and plasm_decimal_avg, Plasm.Sqlite's own window functions (Windows.fs, through sqlite3_create_window_function), adding the decimals' values exactly; linear, as numeric's are	providers.feature: A window's sum of decimals is the dialect's exact aggregate on SQLite
Every call's thread	Npgsql awaits I/O	Microsoft.Data.Sqlite runs each async call on the caller's thread for the statement's length (an ASP.NET request thread is held for its query; repo.Stream holds one while each row is stepped); only a writer's wait for BEGIN IMMEDIATE moves to the thread pool	src/Plasm.Sqlite/Sqlite.fs: BeginTransaction; the SQLite docs give the measurements
A cancelled token while a statement runs	Npgsql cancels it on the server	Plasm.Sqlite interrupts it on its connection (sqlite3_interrupt), only while the statement is the caller's; through Sqlite.connectionOf it is not interrupted	cancellation.feature
A wait for a busy database	none in WAL beyond a writer's lock; PostgreSQL's readers never wait for writers	in WAL only a writer's BEGIN IMMEDIATE; on a rollback-journal file a read waits for a writer and a COMMIT for readers; each tried a second at a time, hearing the token, up to SqliteOptions.BusyTimeout	cancellation.feature: On a rollback-journal file ...
A list of doubles holding NaN or an infinity	stored (float8[] holds them)	refused on write: a list is JSON, which has neither	array-columns.feature: A double that is not a number cannot be stored in a list on SQLite
List.contains over a list column	an array column; a GIN index can serve it	a scan of each row's JSON (json_each), with nothing like a GIN index to serve it; measured on the native binary when the idle-machine measurements are taken	array-columns.feature: Filtering by a value in an array
A list column's integrity	the column's array type holds only arrays of its element type	TEXT holds what any tool writes; the Ddl's check holds it to a JSON array, and a read of anything else is a materialization error naming the column and the element	array-columns.feature: A list column holding what is not a JSON array ...
A constraint violation's identity	the constraint's name (DbFailure.Constraint), the table, no columns	a unique violation's table and columns; a CHECK's name; no unique or foreign key name. A foreign key's columns are found by running the statement again under a savepoint with the check deferred, comparing pragma_foreign_key_check before and after over the tables the statement can break (an INSERT's or UPDATE's own, and the tables referring to an UPDATE's or DELETE's): two scans of those, on that failure only; the re-run does not hear the caller's token, and is not made once it is cancelled	features/constraints.feature; src/Plasm.Sqlite/ForeignKeys.fs; tests/Plasm.Aot.Sqlite
A foreign key failure in a database with triggers	names its constraint	unnamed (Table None, Columns empty): the statement is not run again, so a trigger never fires twice; the failure stays a database failure, not the field's error	features/constraints.feature: On SQLite a foreign key failure in a database with triggers stays unnamed
A recursive query's cycle	CYCLE key SET plasm_cycle USING plasm_path: the recursive table has plasm_cycle and plasm_path (an array of row values) columns	a plasm_path column, the JSON array of the keys above each row; no plasm_cycle column: a row closing a cycle is left out by the step	features/recursive-queries.feature; src/Plasm.Sqlite/Sqlite.fs (Cycle)
A union stored as its cases' names, as text	a text column: any name is stored, and reading one no case has fails	a text column held to the names by a check Ddl writes, which the schema check compares, label by label	features/column-checks.feature
A comparison of a decimal column	numeric compared by the column's operators: an index on it serves a range	plasm_decimal_compare(column, value): by value, as no index on the TEXT column orders; a range over decimals scans	features/query-semantics.feature: Negating a comparison that cannot be absent is the opposite comparison on SQLite
A sandbox and writers outside it	an outside writer goes on beside the sandbox's transaction (row locks apart)	the sandbox's transaction holds the database's write lock: an outside writer waits for the sandbox to end, and fails after the busy timeout	features/sandbox.feature; tests/Plasm.Specs.Steps/SandboxSteps.fs
A string field over a decimal's column, in the schema check	incompatible: numeric is no text	not told apart: a decimal is stored as TEXT, as a string is	features/schema-check.feature: Incompatible column types are reported on SQLite
Two writers at once	they go on together: a change can land between one's read and its write (stale, a Conflict), and serializable ones can fail as serialization failures	they take turns: the second waits at its BEGIN IMMEDIATE for the first to end, for SqliteOptions.BusyTimeout (tried a second at a time), then writes or fails as a Timeout; nothing lands between a transaction's read and its write	features/providers.feature: Rule: On SQLite writers take turns
A stale copy across two transactions (read in one, written from in a later one)	caught by the version column: Tx.oneAsSeen at the version the caller saw is a Conflict once the row has moved on	caught the same way: only a change landing inside one transaction cannot happen, its BEGIN IMMEDIATE holding the write lock	features/typed-transactions.feature: A copy the caller saw before another change is stale, before anything is decided; A stale copy is refused in one SELECT (both on the SQLite run)
An integer divided by zero	a database failure (SQLSTATE 22012, division_by_zero)	NULL: a non-optional field reading it is a materialisation error	features/streaming.feature: A database failure in the middle of a stream is its last element on SQLite
Statements sent together	a write's statements, and a level's loads, travel in one round trip (a DbBatch)	one statement at a time: SQLite runs in the process, with no network to wait for; the statements and their results are the same	features/round-trips.feature: The same statements, one round trip each, with the same results
A retrying transaction (RetryPolicy.OnSerializationFailure)	run again after a serialization failure or a deadlock	never run again: a SQLite transaction meets neither, holding the write lock from its BEGIN; a busy wait that outlasts SqliteOptions.BusyTimeout is a Timeout, which no policy retries, so the wait is the one the caller chose	features/providers.feature: On SQLite a retrying transaction whose BEGIN outwaits its busy timeout fails once, its steps not run
A locked read (FOR UPDATE, FOR SHARE, NOWAIT, SKIP LOCKED)	the rows locked as asked	refused as unsupported (RowLocking false). A possible later change, breaking no one: inside a write transaction, which holds the database's write lock from its BEGIN, FOR UPDATE's guarantee already holds, so a locked read there could be honoured with no SQL	features/row-locks.feature: A provider without row locks refuses a locked read
